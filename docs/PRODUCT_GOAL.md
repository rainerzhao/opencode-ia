# 集团 BU 云解决方案工作台：当前目标

确认日期：2026-09-13。来源：用户在当前任务中确认产品方向，并要求调整 Goal 后继续。

## 可复制到 App Goal 的完整目标

将 OpenCode 团队 AI 工作台建设为面向集团各 BU、供不超过 20 人团队使用的云解决方案工作台，并交付可部署至公司内网 Linux 的版本。以需求与场景为中心，支持统一核心字段及受控自定义字段、手工记录 IIM/电话沟通和导入资料，也支持经 OpenCode 对话后生成需求草稿、由用户确认保存；关联 BU、负责人、沟通记录、多个持久会话、知识文档和版本化方案。个人会话与内容默认私有，显式确认与授权后才能成为共享资产；原始材料、AI 提炼与人工确认结论分开保存并可追溯。重构我的工作台、需求与场景、方案资产、团队知识库四类产品页面，完善多会话历史分页、检索、归档和恢复。所有 Agent、Skill、Tool 和模型推理仍经 OpenCode，接入公司内部 OpenAI 兼容 API；生产业务数据连接公司云 MySQL，不要求自建数据库容器。保留并完成原内网目标：知识/方案来源追溯、附件、备份恢复、遗留内容接口收敛、开源治理、Linux 配置与运行契约、Provider 联调、可观测性、安全隔离、容量和灾备验收。验证 20 个账号、每人 3 个会话的多轮任务、20 个活跃任务的承载能力、权限隔离、完整历史和故障恢复，区分在线人数、持久会话数、执行槽位及模型 API 限流。每个可验收阶段更新产品 README、执行相应自动化与浏览器验证、中文提交并推送 main，再进入下一阶段；不得将 Demo、模拟或 Mac 验收表述为公司生产上线。

## 约束与范围

- 不替换 OpenCode 为 OpenClaw，不增加绕过 OpenCode 的模型调用通道。
- 不自动接入 IIM、录音或电话系统；当前支持用户主动录入/上传，自动采集需另行授权。
- 不将聊天自动公开，也不因管理员角色默认提供私人正文读取权。
- 统一字段用于团队筛选，扩展字段有名称、类型、校验和版本；不是每人一套不可兼容的自由表单。
- 保留旧数据和已有协议；迁移必须可演练，新模型不得覆盖既有会话/方案。
- 生产使用外部 MySQL；本地/CI 临时数据库和无密钥 Demo 不改变生产选型。
- 不预先承诺吞吐或 SLA，先测量自身 Runtime 承载，再单独报告模型提供方约束。
- 相关阶段验收通过才提交发布；现有未跟踪材料不纳入无关提交。
