# 团队 Skill 中心设计

## 目标

让普通成员把个人经验制作成默认私有的 Skill 草稿，经结构、安全和真实运行校验后人工发布为团队资产；其他成员可以安装、启用、升级和回滚。工作台管理身份、权限、版本、审计和文件落盘，OpenCode 负责发现与执行，工作台不直接调用模型。

## 生命周期

```text
私人草稿 → 校验通过 → 创建者发布 → 成员安装 → 成员启用
                               ↓
                    新版本 → 升级 / 回滚
                               ↓
                         停用 / 归档
```

- 草稿仅创建者可读写；管理员可以治理全部 Skill，但审计记录不复制 Skill 正文。
- 发布版本不可变并对团队可见。发布、升级与回滚必须由人确认。
- 删除默认为归档；永久删除不进入 Stage 4 的普通成员流程。
- 安装和启用分开：安装表示版本已复制到用户受管目录，启用表示 OpenCode 可以发现并使用。

## 分阶段交付

### 4A：草稿与数据模型

- SQLite 增加 `skills`、`skill_versions` 与 `skill_installations`。
- 成员可以创建、查看、修改和归档自己的私人草稿；管理员可以管理全部草稿。
- 初始版本为 `0.1.0`，slug 创建后不可修改；草稿正文只保存 `SKILL.md`，附加文件留到 4B。
- 前端提供可演示的草稿列表与编辑器。

### 4B：校验

- 校验 frontmatter、名称一致性、目录和文件限制、敏感信息、路径逃逸与危险命令。
- 校验报告持久化并可追溯；修改草稿会使旧报告失效。
- 可选的真实运行验收必须经过受限 OpenCode Runtime，失败不得发布。

### 4C：发布、安装与发现

- 只有校验通过的版本可以发布；发布将版本变为不可变并切换团队可见性。
- 安装把不可变包原子写入用户受管目录，启用后验证 OpenCode 能发现该版本；失败自动回滚文件和状态。
- 普通成员可以安装和启用任意团队已发布 Skill。

### 4D：版本与治理

- 创建新草稿版本，完成升级、回滚、停用与归档。
- 创建者管理自己的 Skill，管理员管理全部 Skill；所有状态变化写入审计。
- 完成跨账号、异常中断、原子落盘和真实 OpenCode 发现的端到端验收。

## 数据模型

- `skills`：稳定身份、slug、展示信息、所有者、私有/团队可见性与生命周期状态。
- `skill_versions`：版本号、草稿正文、校验状态、内容摘要和发布时间。`published` 版本不可修改。
- `skill_installations`：用户选择的版本以及 installed/enabled/disabled 状态；同一用户每个 Skill 只有一个当前安装。

所有时间使用 ISO 8601 UTC 字符串。数据库继续使用 STRICT 表、外键、WAL 和版本化迁移。

## API 边界

- `GET /api/skills`：返回调用者可见的 Skill；4A 默认只返回自己的草稿，管理员可返回全部草稿。
- `POST /api/skills`：创建私人草稿与 `0.1.0` 草稿版本。
- `GET /api/skills/:id`：读取可见详情。
- `PATCH /api/skills/:id`：仅修改仍为 draft 的 Skill。
- `DELETE /api/skills/:id`：幂等归档草稿。

所有写请求沿用登录 Session 与 CSRF；跨账号成员访问返回 404，避免确认资源存在。错误只返回稳定代码和安全文案。

## 安全与可靠性

- slug 只允许小写字母、数字和单连字符，长度 2–64；输入有严格字节和字符上限。
- 私人 Skill 正文不进入审计、日志或管理员运行元数据。
- 发布与安装目录由服务端派生，拒绝软链接、硬链接、特殊文件和路径逃逸，文件权限保持 0600、目录 0700。
- 数据库状态与磁盘安装使用临时目录、校验、原子重命名和补偿回滚。
- Provider 凭证只存在于 OpenCode 配置环境，不写入 Skill 数据库或仓库。

## 验收

- 单元：状态、版本、slug、所有权、不可变性与校验失效。
- API：成员 CRUD、跨账号 404、管理员治理、CSRF、归档幂等和安全审计。
- 前端：创建、编辑、切换与归档；桌面和 390px 窄屏无横向溢出。
- 4C/4D 真实验收：OpenCode 发现正确版本，升级与回滚后执行结果匹配目标版本。

Mac 验收不等于 Linux 生产就绪。Linux 服务账号、OS 沙箱、备份恢复、内部 Provider 和长期容量仍属于 Stage 5。
