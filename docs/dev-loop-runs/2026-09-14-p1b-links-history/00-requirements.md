# P1B 需求关联与完整历史

## Goal

让一个默认私有需求关联多个本人 Conversation、知识和版本化方案，并提供可分页读取的完整 Conversation 事件历史。

## User-visible Behavior

- 用户从自己的需求中关联或移除自己的 Conversation、知识、方案；同一资产不能重复关联。
- 知识/方案关联固定到关联时的当前版本；后续编辑不篡改已关联版本。
- 获取需求时返回关系卡片，不复制资产正文；关系不能赋予新访问权。
- 受认证用户可分页读取自己 Conversation 的完整事件历史；这与 WebSocket 的短窗口重放并存，后者继续用于实时恢复。

## Acceptance Criteria

- SQLite/MySQL 追加迁移、生产组合和重启读取通过。
- 其他成员及管理员不能用需求关联查看私有 Conversation/知识/方案，且链接错误均为 404。
- 不能关联他人资产、已归档 Conversation 或重复关系；解除关系不删除源资产。
- 分页历史有稳定游标、`hasMore`，不以 1,000 条 WebSocket 重放上限为用户历史上限。
- 路由需要登录和 CSRF；审计只存关系类型/ID/版本，不存正文。

## Non-goals

- 不自动把会话/需求公开；不做跨人转交或团队共享资产引用。
- 不改变 OpenCode 上下文提交策略；不把全部历史自动塞入模型。
- 前端页面和浏览器体验属于 P2。
