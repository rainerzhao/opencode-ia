模拟 Gateway 容量回归通过

P3A：20 位成员可以同时保持工作上下文

工作台将“在线连接”“持久 Conversation”和“模型执行槽”分开承载：20 名成员各一条浏览器连接，每人保留 3 个私有 Conversation，由 5 个受控执行槽公平处理任务。

本次验证

npm run test:capacity:20 完成 20 账号、20 WebSocket、60 Conversation、3 轮共 180 个任务；最大运行 5、单用户最大运行 1、队列峰值 55。每一轮都校验会话标识连续、不同会话不串话、跨账号读取返回 404。

为什么不是 60 条连接

Conversation 是持久业务上下文，不是用户的浏览器连接。原测试一度以每个 Conversation 建连接，触发在线连接上限 20；现已按真实产品模型改为每位成员一条连接订阅自己的多个 Conversation。

边界

这是本机模拟 Worker 的工作台调度和隔离验收，不是公司模型吞吐或 Linux 生产 SLA。真实 20×3×3 需要配置内部 Provider 后以显式命令执行，并在 Linux/云 MySQL 环境做长稳与灾备演练。
