Stage 1A–1B 产品底座评审摘要

从可演示原型，推进到具备持久账号与安全 Session 的后端产品底座

STATUS · STAGE 1B PASS DATE · 2026-09-02 BRANCH · MAIN
TL;DR
Stage 1A 建立 SQLite、迁移、账号与审计仓储；Stage 1B 接通登录、Cookie/CSRF、Session 撤销、限速和管理员账号 API。所有 AI 执行仍只经过 OpenCode，仓库不保存 Provider 密钥。当前业务 REST/WebSocket 尚未切换到强制认证，前端也没有登录页，因此仍是开发版本，不能直接作为内网多用户生产系统开放。

01本次解决的问题

IDENTITY
账号身份
身份来自用户名和密码，不来自办公电脑 IP；管理员建号，不开放自注册。
SESSION
会话安全
浏览器只持有高熵不透明 Cookie，数据库仅保存 Session 与 CSRF 摘要。
CONTROL
账号控制
管理员可建号、重置密码、停用账号和撤销 Session，成员不能调用管理接口。

03测试与审查

  • 真实边界。使用临时 SQLite、真实 HTTP 监听、Cookie 与 CSRF 请求完成集成测试，不以 mock 代替认证链路。
  • 错误一致。不存在的账号、错误密码和停用账号使用同一无泄漏错误；Session 失效返回稳定错误码。
  • 审查修复。成功登录不再清空来源 IP 的失败累计，避免持有任意有效账号后绕过 IP 维度限速。
  • 缓存边界。认证和管理员响应统一设置 Cache-Control: no-store。
  • 发布门禁。npm test、npm run check、npm run security:scan 和 git diff --check 在提交前重新执行。

04残余边界与下一步

NOT PRODUCTION READY
Stage 1B 只保护新增加的认证和管理员 API。现有知识、方案、Skill、上传和 WebSocket 仍保留 Stage 0 的匿名行为，以避免在独立验收点之前造成半完成切换。

Stage 1C 将统一保护 REST 与 WebSocket，把登录用户写入业务审计，并实现成员之间的默认私有隔离。随后 Stage 1D 接入前端登录与账号管理，Stage 1E 完成 React/Vite 迁移和 Stage 1 总验收。
